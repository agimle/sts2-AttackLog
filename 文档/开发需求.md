# 开发需求

## 项目概述

### 项目名称
战斗日志Mod (Attack Log Mod)

### 目标游戏
杀戮尖塔2 (Slay the Spire 2)

### 项目目标
为玩家提供详细的战斗数据统计和分析功能，帮助玩家了解战斗过程中的伤害、护盾、Buff等关键数据，提升游戏体验和策略深度。

---

## 技术实现需求

### 1. 数据收集层

#### 1.1 Hook事件监听
基于Hook系统实现数据收集：

| 数据类型 | 主要Hook |
|---------|----------|
| 伤害数据 | BeforeAttack, AfterAttack, AfterDamageReceived, ModifyDamage |
| 护盾数据 | BeforeBlockGained, AfterBlockGained, AfterBlockBroken |
| 回合数据 | BeforeSideTurnStart, AfterTurnEnd |
| 能力数据 | BeforePowerAmountChanged, AfterPowerAmountChanged |
| 卡牌数据 | BeforeCardPlayed, AfterCardPlayed, AfterCardDrawn |
| 能量数据 | AfterEnergySpent, AfterEnergyReset |
| 球体数据 | AfterOrbChanneled, AfterOrbEvoked |
| 药水数据 | BeforePotionUsed, AfterPotionUsed |

#### 1.2 CombatHistory集成
利用游戏内置的CombatHistory系统获取历史数据：
- DamageReceivedEntry - 伤害记录
- BlockGainedEntry - 护盾记录
- CardPlayedEntry - 卡牌使用记录
- PowerGainedEntry - 能力获得记录

### 2. 数据存储层

#### 2.1 数据结构设计
```
CombatLogData
├── CombatInfo (战斗基础信息)
├── RoundData[] (回合数据)
│   ├── DamageData
│   ├── BlockData
│   ├── EnergyData
│   └── CardData[]
├── PlayerStats (玩家统计)
├── EnemyStats[] (敌人统计)
└── Summary (战斗总结)
```

#### 2.2 数据持久化
- 战斗数据本地存储
- 数据压缩优化
- 历史数据清理策略

### 3. 数据展示层

#### 3.1 UI框架
- 基于游戏UI系统
- 自定义面板组件
- 数据图表组件

#### 3.2 性能优化
- 数据缓存机制
- 延迟加载策略
- 内存使用优化

## 性能需求

### 1. 响应时间
- 数据收集延迟 < 1ms
- UI响应时间 < 100ms
- 战斗报告生成 < 500ms

### 2. 内存占用
- 运行时内存 < 50MB
- 单场战斗数据 < 1MB
- 历史数据存储 < 100MB

### 3. 兼容性
- 不影响游戏原有性能
- 与其他Mod兼容
- 支持多人游戏模式
