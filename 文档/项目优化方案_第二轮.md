## 架构优化方案

### 1. Service 层依赖注入完善

#### 当前问题

Service 类虽然通过 ServiceLocator 管理，但内部仍直接访问 `LogState.Instance`，没有真正实现依赖注入：

```csharp
// AttackLogCombatService 中大量直接访问
private void CreateNewRoomLog(...)
{
    if (LogState.Instance.RunLog is null || runState is null) return;
    LogState.Instance.OnCombatStart();
    foreach (var player in LogState.Instance.RunLog.GetAllPlayers()) { ... }
    LogState.Instance.RoomLogsData.TryAdd(player.PlayerInfo, newRoomLogData);
    LogState.Instance.InvalidateCache();
}
```

**问题**：
- Service 与 LogState 紧耦合，无法独立测试
- 无法在测试中替换 LogState
- 违反依赖倒置原则

#### 优化方案

**通过构造函数注入 LogState**：

```csharp
public interface IAttackLogService
{
    void Subscribe();
    void Unsubscribe();
}

public abstract class AttackLogServiceBase : IAttackLogService
{
    protected readonly LogState State;

    protected AttackLogServiceBase(LogState state)
    {
        State = state;
    }

    public abstract void Subscribe();
    public abstract void Unsubscribe();
}

public class AttackLogCombatService : AttackLogServiceBase
{
    public AttackLogCombatService(LogState state) : base(state) { }

    private void CreateNewRoomLog(IRunState? runState, CombatState? combatState)
    {
        if (State.RunLog is null || runState is null) return;
        State.OnCombatStart();
        foreach (var player in State.RunLog.GetAllPlayers()) { ... }
    }
}
```

**ServiceLocator 相应调整**：

```csharp
public static class AttackLogServiceLocator
{
    private static readonly Dictionary<Type, IAttackLogService> _services = new();

    public static void Initialize(LogState logState)
    {
        _services[typeof(AttackLogCombatService)] = new AttackLogCombatService(logState);
        _services[typeof(AttackLogDamageService)] = new AttackLogDamageService(logState);
        _services[typeof(AttackLogPowerService)] = new AttackLogPowerService(logState);
        _services[typeof(AttackLogRunService)] = new AttackLogRunService(logState);

        foreach (var service in _services.Values)
            service.Subscribe();
    }
}
```

**收益**：
- Service 可独立测试
- 可在测试中注入 Mock LogState
- 符合依赖倒置原则

## 代码质量优化方案

### 1. 事件处理器类型安全

#### 当前问题

Service 层事件处理器使用强制类型转换，没有类型检查：

```csharp
private void OnBeforeCombatStart(IAttackLogEvent e)
{
    var evt = (BeforeCombatStartEvent)e;  // 不安全转换
    CreateNewRoomLog(evt.RunState, evt.CombatState);
}
```

如果事件类型与处理器不匹配，将抛出 `InvalidCastException`。

#### 优化方案

**方案 A：泛型事件总线（推荐）**

```csharp
public static class AttackLogEventBus
{
    public static void Subscribe<T>(Action<T> handler) where T : IAttackLogEvent
    {
        var type = default(T).Type;
        if (!Subscribers.ContainsKey(type))
            Subscribers[type] = new List<Action<IAttackLogEvent>>();
        Subscribers[type].Add(e => handler((T)e));
    }

    public static void Unsubscribe<T>(Action<T> handler) where T : IAttackLogEvent { ... }
}
```

**使用方式**：

```csharp
public class AttackLogCombatService : AttackLogServiceBase
{
    public override void Subscribe()
    {
        AttackLogEventBus.Subscribe<BeforeCombatStartEvent>(OnBeforeCombatStart);
        AttackLogEventBus.Subscribe<AfterCombatEndEvent>(OnAfterCombatEnd);
    }

    private void OnBeforeCombatStart(BeforeCombatStartEvent evt)
    {
        CreateNewRoomLog(evt.RunState, evt.CombatState);
    }
}
```

**方案 B：安全转换 + 日志**

```csharp
private void OnBeforeCombatStart(IAttackLogEvent e)
{
    if (e is not BeforeCombatStartEvent evt)
    {
        ModLogger.Log("CombatService", $"Unexpected event type: {e.Type}");
        return;
    }
    CreateNewRoomLog(evt.RunState, evt.CombatState);
}
```

**推荐**：方案 A，从根源消除类型转换问题。

### 2. 存档异常处理

#### 当前问题

`ModSaveUtils` 中多处空 catch 块，异常被完全吞没：

```csharp
public static void Load(IRunState runState)
{
    try
    {
        string saveJson = File.ReadAllText(ModSaveConfig.SavePath);
        ModSave? modSave = JsonSerializer.Deserialize<ModSave>(saveJson, ModSaveConfig.JsonOptions);
        // ...
    }
    catch (Exception ex)
    {
        // 空catch - 异常被吞没
    }
}

public static void Save(IRunState? runState, CombatState? combatState)
{
    try
    {
        string saveJson = JsonSerializer.Serialize(LogState.Instance.ModSave, ModSaveConfig.JsonOptions);
        File.WriteAllText(ModSaveConfig.SavePath, saveJson);
    }
    catch
    {
        // 空catch - 存档失败无感知
    }
}
```

**风险**：
- 存档损坏时无任何提示
- 调试时无法定位问题
- 用户可能丢失数据而不自知

#### 优化方案

```csharp
public static void Load(IRunState runState)
{
    try
    {
        string saveJson = File.ReadAllText(ModSaveConfig.SavePath);
        ModSave? modSave = JsonSerializer.Deserialize<ModSave>(saveJson, ModSaveConfig.JsonOptions);
        if (modSave == null || modSave.Seed != runState.Rng.Seed)
        {
            LogState.Instance.ModSave = new ModSave(runState);
            OutputData();
        }
        else
        {
            LogState.Instance.ModSave = modSave;
            InputData();
        }
    }
    catch (Exception ex)
    {
        ModLogger.Log("Save", $"Failed to load save: {ex.Message}");
        LogState.Instance.ModSave = new ModSave(runState);
        OutputData();
    }
}

public static void Save(IRunState? runState, CombatState? combatState)
{
    if (LogState.Instance.ModSave == null) return;
    if (runState?.Rng.Seed != LogState.Instance.ModSave.Seed) return;

    OutputData();

    try
    {
        string saveJson = JsonSerializer.Serialize(LogState.Instance.ModSave, ModSaveConfig.JsonOptions);
        File.WriteAllText(ModSaveConfig.SavePath, saveJson);
    }
    catch (Exception ex)
    {
        ModLogger.Log("Save", $"Failed to save: {ex.Message}");
    }
}
```

**收益**：
- 异常有迹可循
- Load 失败时自动创建新存档（降级策略）
- Save 失败时记录日志

### 3. RunLog 查找性能优化

#### 当前问题

`RunLog.GetPlayerByCreature` 使用 `ReferenceEquals` 线性遍历，O(n) 复杂度：

```csharp
public PlayerData? GetPlayerByCreature(Creature creature)
{
    foreach (var playerData in _netIdToPlayers.Values)
    {
        if (ReferenceEquals(playerData.PlayerInfo.Creature, creature))
            return playerData;
    }
    return null;
}
```

在高频调用场景（每次伤害事件都会调用），性能不佳。

#### 优化方案

**添加 Creature → PlayerData 的反向索引**：

```csharp
public class RunLog
{
    private readonly IRunState _runState;
    private readonly Dictionary<ulong, PlayerData> _netIdToPlayers = new();
    private readonly Dictionary<int, PlayerData> _creatureIdToPlayers = new();

    public void RegisterPlayer(Player player)
    {
        var playerData = new PlayerData(player);
        _netIdToPlayers.TryAdd(player.NetId, playerData);
        _creatureIdToPlayers.TryAdd(player.Creature.GetInstanceId(), playerData);
    }

    public PlayerData? GetPlayerByCreature(Creature creature)
    {
        int instanceId = creature.GetInstanceId();
        return _creatureIdToPlayers.TryGetValue(instanceId, out var data) ? data : null;
    }
}
```

**收益**：
- O(n) → O(1) 查找
- 高频调用场景性能提升明显
- `GetInstanceId()` 是 Godot 原生方法，稳定可靠

**PlayerInfo 缓存显示名称**：

```csharp
public class CachedPlayerStats
{
    public AttackLogModel? TurnLog { get; set; }
    public AttackLogModel? RoomLog { get; set; }
    public AttackLogModel? RunLog { get; set; }
    public float DamagePercent { get; set; }
    public int TotalDamage { get; set; }

    private string? _percentText;
    private string? _runDamageText;
    private string? _roomDamageText;
    private string? _turnDamageText;
    private int _cachedRunDamage = -1;
    private int _cachedRoomDamage = -1;
    private int _cachedTurnDamage = -1;
    private float _cachedPercent = -1;

    public string PercentText => _cachedPercent != DamagePercent
        ? (_percentText = $"{DamagePercent:F1}%", _cachedPercent = DamagePercent)._percentText!

    public string RunDamageText
    {
        get
        {
            int damage = RunLog?.RealDamageDealt ?? 0;
            return _cachedRunDamage != damage
                ? (_runDamageText = damage.ToString(), _cachedRunDamage = damage)._runDamageText!
                : _runDamageText!;
        }
    }
}
```

**收益**：
- 减少字符串分配
- 防抖期间避免重复格式化
- 累积效果明显

### 5. Panel 单例生命周期管理

#### 当前问题

`AttackLogPanel` 的单例管理存在隐患：

```csharp
private static AttackLogPanel? _instance;

public static void EnsureCreated()
{
    if (_instance != null) return;
    // 创建逻辑...
}

public override void _ExitTree()
{
    if (ReferenceEquals(_instance, this)) _instance = null;
    UnsubscribeAll();
}
```

**问题**：
- `_instance` 在 `_Ready` 之前可能为 null 但对象已存在
- 没有处理场景树切换时的清理
- 事件订阅在 `_ExitTree` 中取消，但 `_EnterTree` 中没有重新订阅

#### 优化方案

```csharp
public override void _EnterTree()
{
    Layer = 100;
    Name = nameof(AttackLogPanel);
    _instance = this;
}

public override void _ExitTree()
{
    UnsubscribeAll();
    if (ReferenceEquals(_instance, this))
        _instance = null;
}

public override void _Ready()
{
    BuildUi();
    SetInitialPosition();
    SubscribeAll();
    Refresh();
}
```

**关键改进**：
- `_EnterTree` 中立即设置 `_instance`
- `_Ready` 中订阅事件（而非 `_EnterTree`，避免重复订阅）
- 确保生命周期完整：EnterTree → Ready → ... → ExitTree

```csharp
    // 重新计算所有玩家...
}
```

在 4 人游戏中，每次伤害事件都触发 `InvalidateCache()`，导致全部 4 个玩家的缓存重建。

#### 优化方案

**按需更新 + 脏标记**：

```csharp
public class ViewCache
{
    private Dictionary<PlayerInfo, CachedPlayerStats> _statsCache = new();
    private HashSet<PlayerInfo> _dirtyPlayers = new();
    private bool _percentDirty = false;
    private bool _fullyInvalidated = false;

    public void Invalidate()
    {
        _fullyInvalidated = true;
    }

    public void InvalidatePlayer(PlayerInfo info)
    {
        _dirtyPlayers.Add(info);
        _percentDirty = true;
    }

    public CachedPlayerStats? GetStats(PlayerInfo info)
    {
        if (_fullyInvalidated)
        {
            RebuildCache();
            return _statsCache.TryGetValue(info, out var s) ? s : null;
        }

        if (_dirtyPlayers.Contains(info))
        {
            UpdatePlayerStats(info);
            _dirtyPlayers.Remove(info);
        }

        if (_percentDirty)
        {
            RecalculatePercentages();
            _percentDirty = false;
        }

        return _statsCache.TryGetValue(info, out var stats) ? stats : null;
    }
}
```

**Service 层精确失效**：

```csharp
// AttackLogDamageService 中
private void HandleDamageGiven(...)
{
    // ...
    LogState.Instance.InvalidatePlayerCache(player.PlayerInfo);  // 只标记该玩家脏
}
```

**收益**：
- 伤害事件只更新 1 个玩家的缓存（而非全部 4 个）
- 百分比只在需要时重算
- 减少约 75% 的缓存重建开销

### 3. AttackLogModel.Plus 防御性拷贝

#### 当前问题

`AttackLogModel.Sum` 创建新对象再 Plus，而 `Plus` 直接修改 `this`：

```csharp
public static AttackLogModel Sum(AttackLogModel a, AttackLogModel b)
{
    AttackLogModel result = new AttackLogModel();
    result.Plus(a);  // result.DamageOnBlock += a.DamageOnBlock
    result.Plus(b);  // result.DamageOnBlock += b.DamageOnBlock
    return result;
}
```

`ViewCache.CalculatePlayerStats` 中：

```csharp
private AttackLogModel? GetPlayerRoomLog(PlayerInfo playerInfo)
{
    AttackLogModel? turnLog = GetPlayerTurnLog(playerInfo);
    if (turnLog == null) turnLog = new AttackLogModel();

    return LogState.Instance.RoomLogsData.TryGetValue(playerInfo, out var roomLogData)
        ? AttackLogModel.Sum(roomLogData.RoomLogSum, turnLog)  // 正确：创建新对象
        : new AttackLogModel();
}
```

但 `AttackLogCombatService.SaveTurnLog` 中：

```csharp
roomLogData?.RoomLogSum.Plus(turnLogData.TurnLogSum);  // 直接修改 RoomLogSum
```

`Plus` 方法同时用于"累加到自身"和"求和创建新对象"，语义不清晰。

#### 优化方案

**分离累加和求和语义**：

```csharp
public class AttackLogModel
{
    public void Accumulate(AttackLogModel other)
    {
        DamageOnBlock += other.DamageOnBlock;
        DamageOnHp += other.DamageOnHp;
        OverkillDamage += other.OverkillDamage;
        ShieldGained += other.ShieldGained;
        EffectiveShield += other.EffectiveShield;
        OverShield += other.OverShield;
    }

    public static AttackLogModel Sum(AttackLogModel a, AttackLogModel b)
    {
        var result = new AttackLogModel();
        result.Accumulate(a);
        result.Accumulate(b);
        return result;
    }

    public static AttackLogModel Sum(params AttackLogModel[] logs)
    {
        var result = new AttackLogModel();
        foreach (var log in logs)
            result.Accumulate(log);
        return result;
    }
}
```

**收益**：
- 语义清晰：Accumulate = 累加到自身，Sum = 创建新对象
- 减少误用风险

### 3. ModLogger 改进

#### 当前问题

```csharp
public static class ModLogger
{
    private static readonly StringBuilder StringBuilder = new();

    public static void Log(string message)
    {
        string timestamp = DateTime.Now.ToString("HH:mm:ss.fff");
        string line = $"[{timestamp}] {message}";
        StringBuilder.AppendLine(line);
        File.AppendAllText(LogPath, line + "\n");  // 每次都打开/关闭文件
    }
}
```

**问题**：
- `StringBuilder` 只追加不清除（除了 Clear），可能内存增长
- `File.AppendAllText` 每次调用都打开/关闭文件，I/O 开销大
- 没有日志级别

#### 优化方案

```csharp
public enum LogLevel
{
    Debug,
    Info,
    Warning,
    Error
}

public static class ModLogger
{
    private static readonly string LogPath = ProjectSettings.GlobalizePath("user://attack_log_debug.txt");
    private static LogLevel _minLevel = LogLevel.Info;
    private static readonly StreamWriter? _writer;

    static ModLogger()
    {
        try
        {
            _writer = new StreamWriter(LogPath, append: true) { AutoFlush = false };
        }
        catch { }
    }

    public static void Debug(string message) => Write(LogLevel.Debug, message);
    public static void Info(string message) => Write(LogLevel.Info, message);
    public static void Warning(string message) => Write(LogLevel.Warning, message);
    public static void Error(string message) => Write(LogLevel.Error, message);

    private static void Write(LogLevel level, string message)
    {
        if (level < _minLevel) return;

        string timestamp = DateTime.Now.ToString("HH:mm:ss.fff");
        string line = $"[{timestamp}][{level}] {message}";

        try
        {
            _writer?.WriteLine(line);
            if (level >= LogLevel.Warning)
                _writer?.Flush();
        }
        catch { }
    }

    public static void Flush()
    {
        _writer?.Flush();
    }

    public static void Clear()
    {
        _writer?.Flush();
        _writer?.Close();
        if (File.Exists(LogPath))
            File.Delete(LogPath);
    }
}
```

**收益**：
- 日志级别控制
- 减少 I/O 开销（批量写入）
- 高级别日志立即刷新
